## 1. 너랑 갈.지도 · MapMates

안녕하세요. SSAFY 16기 김강민, 마예은입니다. 지도에서 장소를 발견하고 일정을 만든 뒤 함께할 동행을 찾는 플랫폼 MapMates를 소개합니다.

## 2. 목차

기획 배경과 업무 분담을 먼저 설명하고 실제 사용자 흐름으로 기능을 소개합니다. 이어서 기술 구조와 DB 설계, 개발 과정의 문제와 검증 결과를 설명하겠습니다.

## 3. 업무분담

기존 프론트 및 백엔드·DB 업무 분담 기록을 기준으로 담당 도메인을 정리했습니다. 김강민은 기획·지도·여행계획·동행과 공통 연동, 마예은은 회원·커뮤니티·댓글·충전소를 담당했습니다. 요구사항과 ERD 검토, 통합 검증과 문서는 함께 확인했습니다.
출처: front/docs/WORK_SPLIT.md, docs/WORK_SPLIT.md, README.md

## 4. 기획 배경

여행 장소를 고르는 일, 일정을 정리하는 일, 함께 갈 사람을 찾는 일을 한 흐름으로 연결하고자 했습니다. 별도로 찾은 관광지를 다시 일정과 모집글에 옮기는 번거로움을 줄이는 것이 출발점입니다. 시장 통계나 사용자 조사 결과를 임의로 가정하지 않았습니다.

## 5. 지도에서 동행까지 이어지는 흐름

소개 화면에서 지도 탐색으로 이동한 뒤 장소를 담고 날짜별 계획을 만듭니다. 저장한 계획을 동행 모집글로 공유하고 신청과 승인을 진행합니다. 댓글과 알림으로 소통하고 여행 경험을 커뮤니티에 남깁니다.

## 6. 지도와 관광지 탐색

실제 로컬 앱과 Kakao Maps SDK로 촬영한 화면입니다. 관광지 검색은 관광정보 DB를 사용하며 지역·유형·검색어와 지도 주변 검색을 지원합니다. 날씨·충전소 등 외부 정보는 각 서비스의 키와 응답 조건에 따라 동작합니다.
화면: build/assets/map.png

## 7. 날짜별 여행계획과 동선

서울에서 함께 걷는 하루라는 시연 계획을 만들었습니다. 방문 시각·메모·예산·정원을 저장하고 날짜별로 일정을 관리합니다. 동선 최적화는 첫 장소와 마지막 장소를 유지하는 비트마스크 DP를 사용합니다. 직선거리 기반 추천이며 도로 이동시간의 최적해를 보장하지 않습니다.
출처: front/docs/ALGORITHM_IMPROVEMENTS.md, back/src/main/java/com/mapmates/travel/

## 8. 동행 신청과 모집자 승인

즉시 참가와 승인제를 선택할 수 있습니다. 승인제에서는 신청 소개를 보낸 뒤 모집자가 승인합니다. 대기 신청은 정원에 포함되지 않으며 승인할 때 정원을 검사합니다. 화면은 같은 계획을 두 브라우저 세션으로 촬영했습니다.

## 9. 커뮤니티와 알림

여행 게시글과 댓글·대댓글로 경험을 나눕니다. 공지·뉴스는 운영자만 작성할 수 있습니다. 동행 신청·승인·댓글·일정 변경은 알림으로 전달하고 읽음 상태를 관리합니다. 오른쪽은 실제 승인 알림입니다.

## 10. 계정 관리와 안전한 참여

회원·프로필 관리, 이메일 비밀번호 복구와 신고·차단을 지원합니다. 신고는 운영자가 검토하고 처리 의견을 남깁니다. 차단은 새로운 상호작용을 제한하되 기존 참가 기록을 자동 삭제하지 않습니다. 모바일 320px와 390px 화면에서 주요 흐름을 검증했습니다.

## 11. 사용한 기술스택

현재 구현은 Java 17과 Jakarta Servlet 6·Tomcat 10.1, JDBC·HikariCP와 MySQL 8입니다. Spring은 사용하지 않았습니다. 브라우저 화면은 HTML·CSS·Vanilla JavaScript로 구성했습니다.
로고 출처: https://github.com/devicons/devicon/tree/v2.17.0/icons (각 상표는 해당 소유자에게 귀속)

## 12. 시스템 아키텍처

정적 화면과 JSON API를 하나의 WAR에 담아 Tomcat에 배포합니다. 브라우저와 API가 같은 출처를 사용하고 서버는 JDBC 연결 풀로 MySQL에 접근합니다. Kakao 길찾기 REST 키는 서버 환경변수에 보관합니다. 계정 복구 메일은 로컬 Mailpit을 사용했습니다. 공개 서버 배포는 진행하지 않았습니다.

## 13. ERD: 도메인 전체 관계

업무 테이블 19개와 스키마 이력 1개로 총 20개입니다. 이 장은 핵심 도메인 관계를 요약하고 전체 컬럼과 확장 테이블은 별도 원본에 제공합니다. hotplaces는 기존 설계 호환용 예약 테이블로 사진 업로드 기능은 현재 연결하지 않았습니다.
최종 기준: db/schema-current.sql; 전체 ERD: docs/diagrams/erd.excalidraw

## 14. 핵심 DB 설계와 무결성

계획당 동행 모집글은 UNIQUE로 제한합니다. 장소는 관광지 content_id를 참조하고 참가·찜은 복합 키로 중복을 막습니다. 신청 승인도 계획의 정원 잠금을 사용합니다. plans.version은 수정 충돌을 검사하고 plan_revisions에 변경 스냅샷을 남깁니다.

## 15. 계획 저장 요청의 처리 과정

여행계획 저장은 Servlet이 요청을 받고 Service가 작성자와 입력·버전을 확인한 뒤 DAO가 SQL을 실행합니다. 계획과 여러 일정의 교체를 하나의 트랜잭션으로 묶습니다. 공유된 계획이 바뀌면 변경 이력과 참가자 알림도 같은 작업에 포함합니다.

## 16. 고민 ① 동시 참가와 수정 충돌

마지막 한 자리에 두 요청이 동시에 들어오면 각 요청이 같은 인원 수를 보고 정원을 초과할 수 있습니다. 계획 행 FOR UPDATE 잠금과 READ COMMITTED를 적용하고 실제 병렬 요청으로 한 건 성공·한 건 충돌을 검증했습니다. 여러 탭 수정은 plans.version을 비교하고 오래된 버전을 409로 거절합니다.

## 17. 고민 ② 계정 복구와 권한

이름·생년월일 확인만으로 비밀번호를 바꾸던 방식을 이메일 링크로 바꿨습니다. 난수 토큰은 20분 동안 한 번 사용할 수 있으며 DB에는 SHA-256 해시만 저장합니다. 비밀번호 변경 시 auth_version을 증가시켜 기존 세션을 무효화합니다. 로그인·복구 요청 제한은 단일 JVM 메모리 기준입니다.

## 18. 고민 ③ 조회 성능 개선

같은 로컬 Docker DB에서 워밍업 10회 후 60회씩 순차 측정했습니다. 계획 50개·일정 500개의 목록 중앙값은 365.68ms에서 4.87ms로 감소했습니다. 계획별 일정 N+1 조회를 일괄 조회로 바꿨고, 관광지에는 복합 인덱스와 통계 갱신을 적용했습니다. 응답 JSON SHA-256이 전후 일치했습니다. 운영 부하 테스트 결과는 아닙니다.
출처: docs/benchmarks/before.json, after.json, README.md

## 19. 검증과 형상관리

기본 API 7개와 확장 API 9개 시나리오, 데스크톱 12개와 모바일 320px·390px 승인·알림·신고 흐름을 검증했습니다. 이메일 복구는 지연·오류·재시도와 실제 로컬 메일 수신까지 확인했습니다. GitHub Actions의 빌드·API·브라우저·백업/복구 단계가 성공했습니다. GitLab CI는 활성 Runner가 없어 대기 중입니다. 공개 배포는 진행하지 않았습니다.
CI: https://github.com/77romin/mapmates/actions/runs/42473617809

## 20. 회고와 Q&A

화면 중심의 서비스에서 여러 사용자가 함께 쓰는 플랫폼으로 확장하며 데이터 정합성과 권한, 서버 저장의 중요성을 배웠습니다. 추측 대신 동시 요청과 실측으로 문제를 확인하고 개선했습니다. 이상으로 MapMates 발표를 마치겠습니다. 감사합니다.
