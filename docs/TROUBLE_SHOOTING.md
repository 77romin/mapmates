# 너랑 갈.지도 트러블슈팅

개발 과정에서 발생한 문제를 증상, 원인, 해결 방법, 확인 결과 순서로 정리한 문서입니다.

## 빠른 확인표

| 증상 | 우선 확인할 항목 |
| --- | --- |
| 지도가 표시되지 않음 | `KAKAO_JS_KEY`, 카카오 Web 플랫폼 도메인, 개발자 도구 콘솔 |
| 관광지가 항상 제주만 표시됨 | `locationBasedList2` 사용 여부, 지도 `idle` 이벤트, TourAPI 키 |
| 관광지 또는 날씨가 표시되지 않음 | 공공데이터 활용 승인, Decoding 키, API 응답 코드 |
| 차량 경로가 직선으로 표시됨 | `dev-server.js` 실행, `KAKAO_REST_KEY`, `/api/kakao-directions` 응답 |
| 중기예보가 `예보 대기`로 표시됨 | 여행 날짜가 API 제공 기간 안인지, 중기예보 별도 승인 여부 |
| 충전소가 표시되지 않음 | 지도 지역 조회 결과, 충전소 API 키 |
| 새로고침 후 데이터가 사라짐 | `localStorage` 차단·용량·초기화 여부 |
| 프로필 사진 저장 실패 | 이미지 형식·크기, 브라우저 저장 공간 |

## 1. 제주 관광지 30개만 고정으로 표시되는 문제

### 증상

- 지도를 서울이나 부산으로 이동해도 제주 관광지만 표시되었습니다.
- 최초 조회 결과가 30개로 고정되었습니다.

### 원인

초기 구현은 TourAPI `areaBasedList2` 요청에 제주 지역 코드 `39`와 `numOfRows: 30`을 고정해서 사용했습니다. 이 방식은 지도 중심과 관계없이 같은 지역 데이터만 반환합니다.

### 해결

- 지도 중심 좌표를 사용하는 `locationBasedList2`로 주변 검색 API를 분리했습니다.
- 카카오맵의 `idle` 이벤트에서 이동이 끝난 후 데이터를 다시 요청합니다.
- 현재 중심의 위도·경도와 반경을 `mapX`, `mapY`, `radius`로 전달합니다.
- 한 번에 최대 100개를 받아 현재 지도 주변 결과를 목록과 마커에 함께 반영합니다.
- 지도 이동 중 API가 과도하게 호출되지 않도록 350ms 지연을 적용했습니다.

```js
window.kakao.maps.event.addListener(kakaoMap, "idle", () => {
  clearTimeout(mapIdleTimer);
  mapIdleTimer = setTimeout(refreshNearbyFromMap, 350);
});
```

### 비동기 응답 순서 처리

사용자가 지도를 연속으로 이동하면 이전 위치 요청이 나중에 도착해 최신 결과를 덮어쓸 수 있습니다. 중심 좌표로 `fetchKey`를 만들고, 응답 시점에 최신 키와 다르면 결과를 버리도록 처리했습니다.

### 결과

지도를 이동할 때 현재 중심 반경의 여행지로 카드와 마커가 함께 갱신됩니다.

## 2. 지도 드래그·휠 확대가 동작하지 않는 문제

### 증상

지도처럼 보이는 배경은 표시되지만 마우스로 이동하거나 휠로 확대·축소할 수 없었습니다.

### 원인

초기 화면은 정적 지도 형태의 UI였고 실제 카카오맵 인스턴스가 지도 영역에 연결되지 않았습니다. 지도 위 레이어의 쌓임 순서도 함께 정리할 필요가 있었습니다.

### 해결

- `#map-stage` 내부에 실제 카카오맵 컨테이너를 생성했습니다.
- 지도 인스턴스에 드래그와 휠 확대·축소를 명시적으로 활성화했습니다.
- 지도, 경로, 마커, 패널의 `z-index`를 분리했습니다.
- 좌측 패널을 접거나 펼친 뒤 지도 크기가 바뀌면 `relayout()`을 호출했습니다.

```js
kakaoMap.setDraggable(true);
kakaoMap.setZoomable(true);
```

### 결과

마우스 드래그, 휠 확대·축소, 패널 토글 후 지도 재배치가 정상 동작합니다.

## 3. 카카오모빌리티 경로 대신 직선만 표시되는 문제

### 증상

- 여행지 사이가 점선 직선으로만 연결되었습니다.
- 브라우저에서 카카오모빌리티 REST API를 직접 호출하면 CORS 또는 인증 오류가 발생했습니다.

### 원인

지도 위의 두 좌표를 단순 연결한 선은 실제 도로 경로가 아닙니다. 실제 차량 경로에는 카카오모빌리티 Directions API가 필요하며, 브라우저에서 REST 키를 포함한 외부 요청을 직접 보내면 CORS 제약과 키 노출 문제가 생깁니다.

### 해결

- `dev-server.js`에 `/api/kakao-directions` 프록시를 추가했습니다.
- 프론트엔드는 동일 출처의 프록시로 출발지, 경유지, 목적지를 전달합니다.
- 서버가 Authorization 헤더를 포함해 카카오모빌리티 API로 요청합니다.
- 응답의 `roads[].vertexes`를 `[경도, 위도]` 쌍으로 변환해 카카오맵 Polyline으로 그립니다.
- API 요청이 실패하면 화면이 깨지지 않도록 직선 경로로 대체합니다.

### 확인 방법

1. `node dev-server.js`로 실행합니다.
2. `config.js`의 `KAKAO_REST_KEY`와 `API_PROXY_URL`을 확인합니다.
3. 여행계획에서 `차량`을 선택합니다.
4. 개발자 도구 Network 탭에서 `/api/kakao-directions` 응답 상태를 확인합니다.

### 결과

차량 모드에서는 실제 도로 형상의 추천 경로와 이동 거리·시간이 표시되고, 장애 상황에서는 직선 경로가 안전하게 유지됩니다.

## 4. 공공데이터 API 키를 넣었는데 인증 오류가 발생하는 문제

### 증상

- 키를 입력했는데 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 또는 인증 관련 오류가 발생했습니다.
- 브라우저 요청 URL의 `serviceKey`에 `%25`가 반복되어 보였습니다.

### 원인

공공데이터포털은 Encoding 키와 Decoding 키를 함께 제공합니다. 이미 인코딩된 키를 `URLSearchParams`에 넣으면 `%` 문자가 다시 인코딩되어 이중 인코딩될 수 있습니다. 서비스별 활용 신청이 별도로 필요한 경우도 있습니다.

### 해결

- `config.js`에는 공공데이터포털의 Decoding 키를 사용합니다.
- TourAPI, 기상청 단기예보, 중기예보, 충전소 API의 활용 승인 상태를 각각 확인합니다.
- 키 문자열 앞뒤의 공백과 따옴표 누락을 확인합니다.
- 키를 콘솔이나 Git에 출력하지 않습니다.

```js
window.APP_CONFIG = {
  TOUR_API_KEY: "발급받은 Decoding 키",
  WEATHER_API_KEY: "발급받은 Decoding 키",
  EV_CHARGER_API_KEY: "발급받은 Decoding 키",
};
```

## 5. 현재 날씨만 표시되고 여행 기간 날씨가 보이지 않는 문제

### 증상

- 지도에는 현재 시점의 날씨 한 건만 표시되었습니다.
- 여행계획 날짜가 며칠 뒤인 경우 단기예보 결과가 없었습니다.

### 원인

기상청 단기예보와 중기예보는 발표 시각과 제공 기간이 다릅니다. 단기예보 하나만 사용하면 먼 여행 날짜를 표시할 수 없고, 중기예보만 사용하면 가까운 시간대의 상세 예보가 부족합니다.

### 해결

- 지도 화면은 단기예보를 날짜별로 묶어 5일 표 형태로 표시합니다.
- 여행계획은 가까운 날짜에 단기예보를 우선 사용합니다.
- 단기예보 범위 밖의 날짜는 중기육상예보와 중기기온예보를 결합합니다.
- 단기예보 기준 시각은 한국 시간의 `02·05·08·11·14·17·20·23시` 중 최신 발표 시각으로 계산합니다.
- 중기예보 기준 시각은 `06시` 또는 `18시` 최신 발표를 사용합니다.
- 지역명에 따라 육상예보 구역 코드와 기온 지점 코드를 선택합니다.

### 결과

여행 일자별로 날씨 아이콘, 상태, 최저·최고기온과 데이터 출처가 표시됩니다. 아직 API 제공 기간에 들어오지 않은 날짜는 잘못된 값을 만들지 않고 `예보 대기`로 표시합니다.

## 6. 전국 전기차 충전소를 모두 그릴 때 지도가 느려지는 문제

### 증상

충전소 전체 데이터를 매번 요청하고 모든 충전기를 마커로 만들면 지도 이동과 확대가 느려졌습니다.

### 원인

한 충전소에 여러 충전기가 존재해 원본 데이터 행 수가 많고, 지도 범위와 관계없는 데이터까지 DOM과 지도 객체로 생성했습니다.

### 해결

- 전체 충전소 데이터 요청은 Promise로 캐시해 중복 호출을 줄였습니다.
- 현재 위치 반경 안의 데이터만 Haversine 거리로 필터링했습니다.
- 같은 `statId`를 가진 충전기를 한 충전소 마커로 묶었습니다.
- 지도가 너무 축소된 상태에서는 마커를 숨기고 확대를 안내합니다.
- 사용자가 충전소 레이어를 켰을 때만 요청합니다.

### 결과

필요한 시점과 범위에서만 충전소 마커를 생성해 지도 조작 성능을 유지합니다.

## 7. TourAPI 여행지를 일정에 넣은 뒤 서브페이지에서 사라지는 문제

### 증상

지도에서 실시간으로 불러온 여행지를 일정에 추가했지만 `planner.html`로 이동하면 장소 이름이나 이미지가 표시되지 않았습니다.

### 원인

초기 일정은 장소 ID만 저장했습니다. TourAPI로 받아온 장소는 지도 페이지 메모리에만 존재하므로 새 페이지의 내장 데이터에서 같은 ID를 찾을 수 없었습니다.

### 해결

- 일정에 추가할 때 장소의 제목, 이미지, 지역, 좌표 등 필요한 정보를 `itineraryPlaces`에 스냅숏으로 함께 저장했습니다.
- 장소 조회 시 내장 데이터에 없으면 `itineraryPlaces`를 대체 데이터로 사용합니다.
- 장소를 일정에서 제거하면 일정 데이터와 스케줄 데이터를 함께 정리합니다.

### 결과

TourAPI 실시간 여행지도 페이지 이동과 새로고침 후 일정에서 정상 표시됩니다.

## 8. 일정 순서와 여행 시각이 일치하지 않는 문제

### 증상

방문 시각을 변경해도 일정 카드의 표시 순서가 그대로였습니다.

### 원인

화면이 장소를 추가한 순서만 사용하고, 일정 정보의 `day`와 `time`을 정렬 기준으로 사용하지 않았습니다.

### 해결

- 장소별로 `day`, `time`, `memo`를 `tripSchedule`에 저장했습니다.
- 렌더링 전에 DAY와 `HH:mm` 값을 기준으로 정렬합니다.
- 시간 또는 DAY를 변경하면 저장 후 즉시 다시 렌더링합니다.

### 결과

각 DAY 안에서 방문 시각순으로 일정이 자동 정렬되며 메모도 새로고침 후 유지됩니다.

## 9. 큰 프로필 사진 때문에 localStorage 저장이 실패하는 문제

### 증상

고해상도 사진을 등록하면 프로필 저장이 실패하거나 `QuotaExceededError`가 발생했습니다.

### 원인

원본 이미지를 Base64 Data URL로 바꾸면 파일 크기가 더 커집니다. 브라우저 `localStorage`는 저장 용량이 작아 원본 사진을 그대로 저장하기 어렵습니다.

### 해결

- 이미지 형식과 10MB 입력 제한을 먼저 검사합니다.
- 이미지 중앙을 정사각형으로 자릅니다.
- Canvas를 사용해 최대 `320×320` JPEG, 품질 `0.85`로 축소합니다.
- 저장 실패를 `persist()`에서 처리하고 사용자에게 안내합니다.

### 결과

프로필 화면과 참가자 목록에서 사용하기 충분한 품질을 유지하면서 저장 용량을 크게 줄였습니다.

## 10. 게시글·댓글·동행 수정 권한이 섞이는 문제

### 증상

화면별로 작성자 판별 로직이 달라지면 다른 사용자의 수정 버튼이 보이거나, 프로필 변경 후 작성자 이름이 이전 값으로 남을 수 있었습니다.

### 원인

닉네임은 변경 가능한 표시값이므로 소유권 판별에 사용할 수 없습니다. 여러 페이지에서 권한 로직을 중복 구현하면 기준도 쉽게 달라집니다.

### 해결

- 변경되지 않는 `CURRENT_USER_ID`와 콘텐츠의 `ownerId`로 소유권을 판별합니다.
- 게시판 권한은 `board.js`, 동행 상태·권한은 `companion-utils.js`로 분리했습니다.
- 닉네임·사진 변경 시 `syncUserProfile()`로 내가 작성한 게시글, 댓글, 모집글, 참가자 정보를 함께 갱신합니다.
- 화면에서 버튼을 숨기는 것에 그치지 않고 이벤트 처리 시에도 소유권을 다시 확인합니다.

### 결과

본인 게시글·댓글·모집글만 수정·삭제할 수 있고 프로필 변경도 관련 화면에 일관되게 반영됩니다.

## 11. 여러 명이 같은 index.html을 수정해 반복적으로 충돌하는 문제

### 증상

지도, 회원, 동행, 커뮤니티 기능을 모두 `index.html`과 하나의 스크립트에서 작업하면서 pull 또는 merge 때 같은 줄에서 충돌이 발생했습니다.

### 원인

화면과 기능의 경계 없이 하나의 파일에 코드가 집중되었고, 공통 상태 구조를 동시에 수정했습니다.

### 해결

- 지도는 `index.html`, 여행계획은 `planner.html`로 분리했습니다.
- 회원·마이페이지·동행·커뮤니티는 각각 별도 HTML과 JS로 분리했습니다.
- 팀원별 파일 소유권을 `WORK_SPLIT.md`에 기록했습니다.
- `shared.js`, 공통 CSS처럼 함께 사용하는 파일은 먼저 합의한 뒤 병합했습니다.
- pull 전 `git status`로 작업 트리를 확인하고, 가능한 경우 `git pull --ff-only`로 예상하지 않은 병합 커밋을 방지했습니다.

### 권장 병합 순서

1. 공통 상태·유틸리티
2. 담당 서브페이지 HTML·JS
3. 공통 스타일

## 2026-10-03 — 충전소 레이어 최초 조회 지연

### 원인

기존 `getAllEvChargers()`는 지역 조건 없이 전국 충전기를 페이지당 9,999건, 최대 20페이지까지 순차 요청했습니다. 데이터를 모두 받은 다음 사용자 GPS 반경 20km를 필터링하므로 화면에 필요한 지역보다 훨씬 많은 데이터를 다운로드하고 JSON 파싱했습니다. 지도 중심과 GPS 위치가 달라지면 보고 있는 지도에 충전소가 나타나지 않았으며 위치 권한 대기까지 추가되었습니다. 마커 표시 확대 수준도 4로 제한돼 버튼을 켜도 아무 결과가 없는 경우가 많았습니다.

### 해결

- 지도 중심을 카카오 역지오코딩해 시도 코드 `zcode`를 얻고 해당 지역만 요청합니다. 충전소 조회에 GPS 권한을 요구하지 않습니다.
- 페이지당 500건, 최대 8페이지(4,000 충전기), 동시 요청 최대 2개로 제한합니다. 첫 페이지부터 표시하며 남은 페이지를 읽는 동안 진행 안내를 보여줍니다.
- 지역별 메모리 캐시를 2분 유지하고 동일 지역의 진행 중 요청을 병합합니다. 실패한 요청은 캐시에 남기지 않아 재시도가 가능합니다.
- 화면 경계와 반경을 모두 확인하고 가까운 충전소 최대 80곳만 표시합니다. 요청 번호로 지도 이동·레이어 OFF 이후 오래된 응답이 마커를 복원하는 것을 차단합니다.
- 네트워크 요청은 12초 제한을 적용합니다. 확대 안내, 조회 실패, 일부 조회 여부, 조회 시간을 표시합니다.
- 전국 일괄조회 함수를 제거했습니다. 일반 지도는 충전소 버튼이 꺼져 있는 동안 충전소 API를 호출하지 않습니다.

### 검증

`tests/api.cjs`에서 지역 조건, 중복 요청 병합, 2개 동시 요청 제한, 8페이지/4,000건 상한, 단계별 표시, 부분 조회 표기, 2분 캐시, 실패 후 재시도, 날씨 캐시를 검증했습니다.

실제 Chrome + 서울 지도 중심 테스트(2026-10-03): 첫 진행 안내 시점(약 0.5초)에 주변 충전소 24곳, 최종 조회 약 1.4초/8요청/80곳 표시. 같은 지역 OFF→ON은 추가 요청 0건, OFF 이후 보이는 충전소 마커 0개, JavaScript 오류 0개였습니다. 공공 API 응답 속도와 데이터량에 따라 시간은 달라집니다. 기존 구현의 실측 시간을 기록하지 않았으므로 배수 개선 수치는 제시하지 않습니다.

### 남은 한계

시도 데이터가 4,000건을 넘으면 일부만 조회됩니다. 이를 전체 충전소 결과로 표현하지 않고 ‘지역 일부 조회’라고 표시합니다. 이 제한 때문에 현재 지도에 존재하는 모든 충전소를 보장하지는 않습니다. 백엔드 도입 시 전체 데이터를 주기적으로 수집하고 공간 인덱스로 지도 범위만 조회하며, 상태 정보는 별도로 갱신하는 것이 후속 과제입니다. 충전 상태는 조회 시점의 데이터이며 2분 캐시 동안 변경될 수 있습니다.

공식 참고: [한국환경공단 전기자동차 충전소 정보](https://www.data.go.kr/data/15076352/openapi.do).

## 2026-10-03 — 계정 전환 시 콘텐츠 삭제와 권한 혼선

기존 회원가입은 브라우저당 한 계정만 허용하고 새 회원 가입 시 기존 회원의 글·댓글·모집글을 삭제했습니다. 모든 계정이 `user-me` ID를 사용했고 처음 방문부터 로그인 상태였습니다.

회원 목록 `members`와 현재 세션을 분리하고 새 회원은 UUID를 발급합니다. 모든 작성·수정·삭제·참가 권한은 실제 현재 회원 ID로 검사합니다. 회원별 초안 `drafts`와 저장 계획 `plans`를 분리하고 로그아웃 시 회원 초안을 저장한 후 게스트 초안으로 복귀합니다. 게스트가 준비한 일정은 로그인 후에도 유지합니다. 탈퇴는 해당 회원의 콘텐츠·계획·참가 기록만 정리합니다. 비밀번호 재설정은 회원 정보 확인을 이용한 로컬 체험이며 실제 메일을 발송하지 않습니다.

검증: 서로 다른 체험 계정에서 게시글·댓글 권한과 동행 참가·취소를 확인했고, 별도 가입·중복 이메일·비밀번호 재설정·로그인·탈퇴를 브라우저에서 검증했습니다.

## 2026-10-03 — 여행계획과 동행이 따로 갱신되는 문제

이전에는 제목으로 공유 계획을 찾고 지역은 제주로 고정했으며, 재공유 시 상태를 초기화했습니다. 여행 기간과 무관하게 DAY 1~3만 존재했습니다.

계획에 고유 `trip.id`를 부여하고 회원별 여러 계획을 저장합니다. 기간은 1~14일, 정원은 2~10명으로 검사합니다. 동행은 `tripId`로 원래 계획과 연결하고 공유 시 장소 정보와 일정의 복사본을 저장합니다. 업데이트는 참가자와 수동 마감을 유지합니다. 참가 전에도 상세 일정을 열람할 수 있고 모집자는 바로 ‘참여마감’ 또는 ‘참여모집 다시 열기’를 선택합니다. 정원이 찬 경우 자동 마감되며 참가 취소로 자리가 나면 다시 열리지만 수동 마감은 유지됩니다. 지도 일정 순서 변경은 방문 시각과 날짜 슬롯에도 반영합니다.

## 2026-10-03 — 데이터 표기·첫 방문·모바일 배치

TourAPI 목록에 기존 데모 장소의 평점·리뷰·날씨와 인덱스로 계산한 가짜 거리가 섞였습니다. 실데이터 카드에서 평점·리뷰를 제거하고 API 거리 또는 지도 중심과 실제 좌표 간 거리로 표시합니다. 여행지 설명과 일출·일몰은 해당 장소 좌표로 조회합니다. 샘플 게시물과 뉴스는 체험 데이터입니다.

날씨는 기본 OFF이며 토글 상태를 저장합니다. 동일 예보 격자·발표 시각은 캐시를 재사용합니다. 최초 소개는 별도 키로 기록하고 깊은 링크 목적지를 보존하며, 좌측 하단 소개 링크로 다시 열 수 있습니다. 모바일 지도 제어의 top/bottom 동시 지정으로 제어 영역이 과도하게 늘어나던 문제를 수정했습니다. 노을 배경은 프로젝트 안에 보관한 AI 생성 이미지입니다.

일출·일몰 API도 추가로 확인했습니다. v2는 v1처럼 `results` 아래에 시간을 넣지 않고 응답 최상위에 ISO 8601 시간을 제공합니다. 기존 v1 형태의 파싱을 수정했고 `tz=Asia/Seoul`과 한국 표준시 시각 포맷, 응답 실패 안내, 공급자 링크를 적용했습니다. 공식 문서: [Sunrise-Sunset API v2](https://sunrise-sunset.org/api).

TourAPI `detailCommon2`도 실제 응답을 검증했습니다. 구버전의 `overviewYN` 등 옵션이 v2에서 `INVALID_REQUEST_PARAMETER_ERROR(overviewYN)`를 반환해 설명이 갱신되지 않았습니다. 해당 옵션을 제거하고 `contentId`로 상세를 조회하며, JSON의 결과 코드를 검사하도록 수정했습니다. 실제 서울 음식점에서 관광공사의 상세 설명이 표시되는 것을 확인했습니다.

## 메인 지도에 의미 없는 빨간 선이 표시됨 (2026-10-03)
- 원인: 첫 방문에도 기본/저장 초안의 일정이 지도에 자동으로 그려져, 탐색 중인 지역과 관계없는 빨간 선이 나타났다.
- 해결: 탐색에서는 일정 선을 표시하지 않는다. 둘러보기·내 여행에서 사용자가 선택한 여행의 해당 DAY만 번호 마커와 함께 표시하고 지도를 해당 위치로 이동한다. 여행 변경/일차 변경 시 이전 선과 마커를 제거한다.

## 동행 상세 지도 갱신과 로드뷰
- 동행 상세와 메인 지도에서 경로 표시 모듈을 공유한다. 지도 SDK가 만든 컨테이너 내부 DOM을 지우면 SDK의 `insertBefore` 오류가 발생하므로, 실제 지도 연결 후에는 생성한 오버레이만 제거하고 컨테이너를 유지한다.
- 지도 아이콘 아래에 일반·스카이뷰·로드뷰·지형도를 한 열로 제공한다. 로드뷰에서 파란 도로를 더블클릭하면 `RoadviewClient.getNearestPanoId`로 가까운 파노라마를 찾아 네이티브 dialog에 표시한다. 팝업 안에서 드래그·도로 이동 화살표를 사용할 수 있다. 파노라마가 없으면 안내하고 닫기/Escape로 지도로 돌아온다.
- 구현 참고: https://apis.map.kakao.com/web/documentation/ 및 https://apis.map.kakao.com/web/sample/basicRoadview/

## 체험 여행의 차량경로가 실패함
- 최종 검증을 실제 차량 경로 성공으로 강화하자 부산 일정의 일부 구간에서 카카오모빌리티 `result_code: 103`(도착 지점 주변 도로 탐색 불가)이 확인됐다. 더미 장소를 지역 기준점+임의 간격으로 만들면서 일부 좌표가 바다에 위치한 것이 원인이었다.
- 부산·서울·강원 체험 장소 좌표를 카카오 Places 검색 결과로 보정했다. 기존 저장소는 일회성 좌표 마이그레이션으로 동행·저장계획·초안에 반영하며, 원래 더미 제목과 기존 좌표가 모두 일치하는 항목만 수정한다. 사용자가 수정한 장소나 게시물·회원·참여 정보는 유지한다.
- `tests/workspace.cjs`는 기존 잘못된 좌표를 저장소에 재현한 뒤 복구를 확인하고, 차량경로 상태가 실제 차량경로 성공인지 검사한다. 실패 후 직선 대체 메시지만으로 통과하지 않는다.

## 여행 카드와 상세 화면 분리 (2026-10-03 추가 수정)
- 문제: 여행 선택 후에도 모든 여행 카드가 상세 아래에 남아 스크롤이 길어졌고, 경로 드롭다운과 상세·참가 링크가 카드 안에 함께 노출됐다.
- 해결: 둘러보기/내 여행에 사진이 있는 2열 카드 목록을 제공한다. 선택하면 목록을 숨기고 해당 여행 정보, 직선/차량경로 토글, DAY 버튼, 날씨, 방문 장소와 ‘세부내용 보기’만 표시한다. ‘목록으로’ 버튼은 경로와 마커를 정리하고 카드 목록으로 돌아간다.
- 직선과 실제 차량경로는 모두 붉은 실선이다. 토글은 `aria-pressed`로 현재 경로를 표시하며, 경로 변경 시 선택 DAY를 유지한다.
- 내 여행의 새 여행 작성은 `planner.html?new=1`로 연결한다. 페이지는 새 빈 계획을 만든 후 쿼리를 제거하므로 새로고침해도 작성 내용을 초기화하지 않는다. 기존 저장 계획의 세부내용 보기는 해당 계획의 일정·장소를 복원해 계획 페이지를 연다. 빈 일정도 로그인 과정에서 제목과 설정을 보존한다.
- 검증: 실제 차량경로의 Polyline 색상/실선/도로 좌표, 목록 숨김·복귀, 세부 페이지 링크, 새 계획·새로고침, 비로그인 저장 후 복귀, 390px 화면을 Playwright로 확인했다.

## 둘러보기에서 바로 동행 참가
- 선택한 여행 제목 옆 ‘동행하기’ 버튼으로 참가 정보를 저장하고 인원·정원 상태를 갱신한다. 참가 중, 내 모집글, 모집 마감 상태는 버튼을 비활성화한다.
- 클릭 시 저장소를 다시 읽어 다른 탭에서 모집이 마감되거나 참가 정보가 변경된 경우도 반영한다. 저장 실패 시 참가 변경을 되돌린다.
- 비로그인 사용자는 로그인 후 동일한 여행 선택 화면으로 복귀해 참가할 수 있다.
- `tests/workspace-join.cjs`: 직접 참가, 중복 방지, 정원 마감, 모집자·마감 보호, 다른 탭의 마감 반영, 새로고침 보존, 로그인 복귀, 390px 화면과 JavaScript 오류 없음 검증 통과.

## 여행 카드 첫 방문지 썸네일 / 패널 화살표
- 여행 카드는 대표 표지나 장소 객체의 저장 순서가 아니라 일정의 일차·방문 시각을 정렬한 첫 장소 사진을 사용한다. 첫 장소의 사진이 없거나 로딩에 실패하면 기본 노을 이미지를 표시한다.
- 기존 체험 데이터의 공통 표지 사진은 TourAPI에서 확인한 월정리·광안리·경포해변·경복궁 사진으로 보정했다. 저장소에서는 기존 더미 ID·장소명·사진이 일치하는 경우만 한 번 보정해 사용자 지정 사진을 유지한다.
- 패널 접기 버튼 전체에 회전을 적용해 모서리까지 뒤집히던 문제는 화살표를 별도 span으로 분리해 해결했다. 버튼의 위치와 둥근 모서리는 유지하고 화살표만 180도 회전한다.
- 브라우저 확인: 둘러보기/내 여행 첫 방문지 선택(정렬되지 않은 일정 포함), 체험 장소 사진, 접기/펼치기 시 버튼 변형 없음 및 화살표 회전, JavaScript 오류 없음.

## 지도 범위 인기 여행지 TOP 10으로 핫플 변경
- 사용자 요청에 따라 수동 핫플 등록 버튼·폼을 제거했다. 기존 저장 데이터는 보존하지만 인기 순위는 저장된 여행계획만 집계한다.
- 지도 bounds 내부의 계획 장소를 묶고, 같은 회원의 같은 장소 추가는 인원 수에 한 번만 반영한다. 같은 계획에서 반복 방문한 장소도 일정 수는 한 번만 센다. 인기 인원 → 계획 수 → 장소명 순으로 최대 10곳을 목록과 번호 마커로 표시한다. 좌표·이름이 동일한 더미 장소도 하나로 묶는다.
- 지도 idle 시 현재 범위로 다시 집계한다. 핫플을 끄면 목록과 마커를 제거하며, 장소 클릭 후 일정 추가도 저장된 장소 좌표·사진을 유지한다. 현재 집계 범위는 이 브라우저의 로컬 저장 계획이다.
- 여행지 선택 박스는 164px에서 82px로 줄이고 별도 OFF 항목을 제거했다. 모든 유형이 켜진 상태에서 전체를 누르면 모두 OFF, 그 외 상태에서 누르면 모두 ON이다.
- 순위 집계 테스트 및 실제 지도 UI 검증, 최신 62개 통합 회귀 체크 통과.


## 충전소가 축소된 지도에서 숨겨지는 문제

지도 레벨이 7보다 크면 충전소 마커를 모두 지우고 조회를 중단하는 조건이 원인이었습니다. 확대 수준 제한과 확대 안내를 제거해 모든 지도 축척에서 충전소 토글을 사용할 수 있도록 수정했습니다. 지역별 조회, 캐시, 지도 중심 반경 20km 및 최대 80곳 표시는 유지해 대량 조회와 마커 렌더링 부하를 줄입니다.
