# 너랑 갈.지도 · MapMates

**한국어** | [English — 프론트 화면 안내](./front/README-en.md)

> 너랑 갈 다음 여행을 지도 위에 · Find your route. Meet your mates.

**MapMates**는 Map(지도)와 Mates(함께할 친구들)를 합친 영어 이름으로, ‘너랑 갈.지도’의 지도와 동행이라는 의미를 담았습니다.

지도에서 여행지를 발견하고, 나만의 일정을 만든 뒤 함께할 동행을 찾는 여행 웹앱입니다. **소개 → 지도 탐색 → 내 여행 작성 → 동행 공유·참여 → 여행 이야기 나누기** 순서로 사용할 수 있습니다.

HTML·CSS·JavaScript 화면에 **Java Servlet MVC·JDBC·MySQL 백엔드와 DB**를 연결했습니다. 회원·여행계획·찜·동행·게시글·댓글은 서버에 저장하고, 서로 다른 브라우저에서도 같은 여행과 참가 현황을 확인합니다. 브라우저에는 작성 중 초안과 지도 설정을 보관합니다.

## 기획 배경과 서비스 방향

여행 장소를 고르는 일과 일정을 짜는 일, 함께 떠날 동행을 구하는 일을 한 흐름으로 연결하고자 했습니다. 관광지를 따로 찾아 기록하고 다시 모집글을 작성하는 대신, **지도에 담은 장소가 여행계획이 되고 그 계획이 동행 모집글로 이어지는 서비스**를 기획했습니다.

카카오 지도와 공공 관광정보로 장소·주변 환경을 살펴보고, 날짜별 방문 시각·동선·예산을 정리합니다. 저장한 계획을 공유하면 다른 회원이 상세 일정과 참가자를 확인하고 질문한 뒤 참여할 수 있습니다. 여행 후에는 커뮤니티에서 경험을 나눕니다. 날씨·충전소·로드뷰와 동선 최적화는 이 과정에서 여행 준비를 돕는 기능입니다.

프론트 단계에서 완성한 사용 흐름에 서버 인증과 영속 저장을 더해, 한 브라우저의 체험을 넘어 **여러 회원이 계획·동행·이야기를 공유하는 플랫폼**으로 확장했습니다.

## 시스템 구조

![MapMates 프론트엔드 백엔드 데이터베이스와 외부 API 연결 구조](./docs/diagrams/architecture.png)

브라우저의 `front/` 화면이 `server-api.js`를 통해 같은 출처의 `/mapmates/api/*`를 호출합니다. `back/`의 Servlet·Service·DAO와 JDBC가 요청을 처리하고 `db/`의 MySQL에 저장합니다. 정적 화면과 API는 하나의 WAR로 Tomcat에 배포하며, Docker Compose로 Tomcat과 MySQL을 함께 실행합니다.

지도 SDK·날씨·충전소·일출일몰은 브라우저에서 해당 외부 API를 사용합니다. 카카오모빌리티 길찾기는 백엔드 프록시를 거치며 REST 키는 서버에만 둡니다. 구조도의 DB 연결은 JDBC 기반이며 MySQL 포트는 호스트에 공개하지 않습니다.

### 여행지 버튼으로 필터링

지도 위 **여행지** 버튼에서 관광지·맛집·숙소·문화·공연/행사·쇼핑·코스를 각각 켜거나 끕니다. **전체**를 누르면 모든 종류를 켜고, 다시 누르면 모두 끕니다. 선택한 종류에 맞춰 주변 카드와 마커가 갱신됩니다.

![용산구 지도에서 맛집만 선택해 표시한 여행지 필터](./front/docs/screenshots/guide/07-place-filter.png)

### 날씨 버튼으로 5일 예보 확인

**날씨** 버튼을 누르면 현재 지도 중심의 5일 예보를 볼 수 있습니다. 날짜별 날씨와 최저·최고기온을 확인하고 다시 누르면 숨깁니다. 실제 기상청 응답의 제공 기간에 따라 표시되는 날짜 수가 달라질 수 있습니다.

![용산구 중심 지도와 날짜별 날씨 및 최저 최고기온](./front/docs/screenshots/guide/09-weather.png)

### 충전소 버튼으로 충전 현황 확인

**충전소**를 켜면 지도 주변 충전소가 표시됩니다. 번개 마커를 누르면 충전소 이름·주소, **충전 가능한 대수**, 전체 대수, 충전 중인 대수와 충전기별 상태를 확인합니다. 축척에 따른 표시 제한 없이 사용할 수 있으며, 성능을 위해 지도 중심 반경 20km 안에서 최대 80곳을 표시합니다. 지역 일부만 조회된 경우 화면에 안내합니다.

![용산구 중심 지도에 표시한 충전소 핀과 충전 가능 대수 상세](./front/docs/screenshots/guide/10-chargers.png)

### 핫플 — 사람들이 여행계획에 많이 담은 장소

**핫플**을 켜면 현재 지도 범위에서 여행계획에 많이 추가된 장소 **최대 10곳**을 순위로 표시합니다. 장소별로 추가한 회원 수와 일정 수를 함께 볼 수 있습니다. 지도를 이동하면 범위에 맞춰 갱신되고, 장소를 누르면 정보를 보거나 내 일정에 추가할 수 있습니다. 서버 모드에서는 MySQL에 저장된 **전체 회원의 계획**을 집계하며 같은 회원과 같은 계획의 반복 추가는 각각 중복 집계하지 않습니다.

서버 모드는 관광지 ID별 회원 수·계획 수를 SQL로 집계해 상위 10곳을 반환합니다. 프론트 단독 데모에서는 기존 **최소 힙**으로 상위 10곳을 선정합니다. 데모 알고리즘의 합성 후보 10만 개 비교에서는 비교 횟수 **93.4% 감소**를 확인했습니다.

![용산구 주변 체험 계획의 인기 장소 순위와 지도 번호 핀](./front/docs/screenshots/guide/11-hotplaces.png)

오른쪽 아래 **지도 아이콘**을 누르면 일반·위성·로드뷰·지형도 메뉴가 한 열로 펼쳐집니다. 장소 아이콘과 선택한 여행지는 지도 종류를 바꿔도 유지됩니다.

![지도 아이콘 아래에 펼쳐지는 지도 타입 메뉴](./front/docs/screenshots/guide/12-map-types.png)

**일반 지도**는 도로·지명·시설을 확인하기 좋습니다.

![용산구 일반 지도와 종류별 장소 아이콘](./front/docs/screenshots/guide/35-map-normal.png)

**위성 지도**는 항공영상으로 건물과 공원, 강 등 주변 모습을 확인할 수 있습니다.

![용산구 위성 지도와 종류별 장소 아이콘](./front/docs/screenshots/guide/36-map-satellite.png)

**지형도**는 기본 지도 위에 지형 정보를 겹쳐 남산과 주변 지역의 지세를 확인할 수 있습니다. 다시 누르면 지형 표시를 끕니다.

![용산구 일반 지도에 지형 정보를 겹쳐 표시한 화면](./front/docs/screenshots/guide/37-map-terrain.png)

![용산구 중심 지도에서 로드뷰를 켜 파란 도로를 표시한 화면](./front/docs/screenshots/guide/14-roadview-layer.png)

![광화문광장 부근에서 광화문 정면을 바라보는 로드뷰 팝업](./front/docs/screenshots/guide/15-roadview-popup.png)

### 둘러보기 탭에서 공유 여행계획과 동행 참여

**둘러보기**에는 동행찾기에 올라온 공유 여행계획이 사진 카드로 표시됩니다. 카드를 누르면 선택한 여행의 소개·참가 인원·DAY별 일정과 날씨가 나타나며 지도도 해당 동선으로 이동합니다. 직선/차량경로를 바꿔 확인하고, **세부내용 보기**로 동행 상세 페이지를 엽니다.

![로드뷰를 끈 일반 지도와 둘러보기의 공유 여행계획 카드 목록](./front/docs/screenshots/guide/16-browse-cards.png)

제목 옆 **동행하기**를 누르면 바로 참가하고 **참가 중**으로 바뀝니다. 참가 중 버튼을 다시 누르면 취소됩니다. 정원이 찼거나 모집자가 마감한 여행에는 새로 참가할 수 없고, 로그인 전이라면 로그인 후 선택한 여행으로 돌아옵니다.

![선택한 여행의 실제 차량 동선과 동행 참가 중 버튼](./front/docs/screenshots/guide/18-browse-joined.png)

### 내 여행 탭에서 내 계획과 동선 확인

**내 여행** 탭에는 로그인한 내가 작성한 계획만 표시됩니다. 카드 선택 후 **직선 / 차량경로** 토글과 DAY 버튼으로 동선을 확인합니다. 두 경로 모두 붉은 실선으로 표시합니다. **새 여행 작성**은 내 여행 페이지의 새 계획 작성으로, **세부내용 보기**는 선택한 계획의 편집 화면으로 연결됩니다.

![차량경로를 선택해 실제 도로를 따라 표시한 내 여행 동선](./front/docs/screenshots/guide/21-mine-car.png)

## 3. 내 여행 페이지 — 내 계획을 카드로 관리하기

### 저장 계획 목록과 세부 정보

상단 **내 여행** 메뉴에서 내가 저장한 여행을 카드로 확인합니다. 카드에는 첫 방문지 사진·여행 기간·장소 수·지역/테마·공유 여부가 표시됩니다. 카드를 누르면 해당 계획의 세부 일정과 편집 화면으로 이동합니다.

![첫 방문지 사진을 사용하는 내 여행 계획 카드 목록](./front/docs/screenshots/guide/22-plan-library.png)

### 새 여행 작성과 날짜별 장소 추가

**＋ 새 여행**을 누르고 여행 제목, 출발일, 종료일, 동행 정원(나 포함), 예상 여행경비, 지역, 테마, 소개를 입력합니다. 지역은 서울·경기·강원·충남·충북·경남·경북·전남·전북·제주·기타 중 선택할 수 있습니다.

![여행 제목 기간 정원 경비 지역 테마 소개를 입력하는 새 계획](./front/docs/screenshots/guide/24-new-plan.png)

예상 여행 정보 아래 **＋ 장소 추가**를 누르면 지도 탐색으로 이동합니다. 여행지 상세에서 **일정 추가**로 담은 후 내 여행으로 돌아와 각 장소의 DAY·방문 시각·메모를 정리합니다. 일정은 방문 시각순으로 정렬되고 날짜별 날씨와 경로, 예상 이동 거리·시간을 확인할 수 있습니다.

![DAY별 장소와 방문 시각 메모 지도 및 예상 이동 정보를 확인하는 계획 상세](./front/docs/screenshots/guide/23-plan-details.png)

## 화면 캡처 안내

화면별 사용법의 기존 이미지는 2026-10-03 당시 앱을 별도 Chrome 브라우저에서 직접 조작해 캡처했습니다. 기존 캡처는 기능의 사용 순서를 보여주며, 현재 서버 연동 검증 화면은 바로 위 절에 구분해 실었습니다. 지도·날씨·충전소·로드뷰는 실제 API 화면이고, 회원·여행계획·질문·게시글은 브라우저 체험 데이터입니다. 촬영을 위한 가입·작성·참가 작업은 사용자의 기존 브라우저 데이터를 변경하지 않습니다. 외부 API 응답, 지도 위치, 로그인 계정과 데이터에 따라 표시 내용은 달라질 수 있습니다.

주변 여행지·필터·충전소·핫플 4개 캡처는 **2026-10-15 용산구 중심, 지도 하단 축척 막대 500m**로 다시 촬영했습니다. 충전소와 핫플은 검색 패널과 일반 여행지 핀을 숨겨 해당 핀이 잘 보이게 했습니다. 관광지·지도·충전 현황은 실제 API 응답이며, 핫플 집계는 실제 관광지 좌표를 담은 별도 브라우저의 촬영용 체험 계획을 사용했습니다.

날씨·지도 타입·로드뷰 도로 표시도 같은 용산구 범위로 갱신했습니다. 로드뷰 팝업은 광화문광장에서 광화문을 바라본 화면이며, 둘러보기는 로드뷰를 끈 일반 지도입니다. 동행 참가·내 여행의 동선 확인 화면은 카카오모빌리티 응답으로 실제 차량 경로를 표시한 상태로 촬영했습니다.

종류별 지도 아이콘 적용 후 메인 지도 캡처를 다시 촬영했으며, 일반·위성·지형도 3종도 동일한 용산구 중심과 축척으로 비교할 수 있게 추가했습니다.

## 알고리즘 적용

내 여행의 **동선 최적화**는 비트마스크 DP로 첫 장소와 마지막 장소를 유지하면서 하루 방문 순서를 추천합니다. 적용 전에 직선거리와 새 방문 시각을 비교하고, 적용 직후 되돌릴 수 있습니다. 프론트 단독 데모의 **핫플 TOP 10**은 최소 힙으로 상위 장소를 선정하고, 서버 모드의 핫플은 전체 회원의 DB 계획을 집계합니다.

기존 8개 장소 예시에서 직선거리 **31.0% 감소**, 합성 후보 10만 개의 TOP 10 선정에서 비교 횟수 **93.4% 감소**를 확인했습니다. 측정 조건·제한과 구현 내용은 [알고리즘 적용 기획 및 정량 검증](./front/docs/ALGORITHM_IMPROVEMENTS.md)을 참고하세요.

| 서울 중심 5km 주변 관광지 | 6.81 / 7.53 | 4.15 / 4.71 | 39.1% |
| 관광지 이름에 박물관 포함 | 15.36 / 22.78 | 8.03 / 15.93 | 47.7% |

계획별 일정 조회를 일괄 조회로 바꾸고, 관광지 페이지 정렬용 복합 인덱스와 통계 갱신을 적용했습니다. 그래프의 막대는 중앙값, 마름모는 p95이며 두 패널의 세로축 범위는 다릅니다. 단일 로컬 실행 결과이며 운영 부하 성능을 의미하지 않습니다. 주변·키워드 검색은 통계와 실행 환경 영향을 포함한 비교 항목입니다. [측정 조건·원시 표본·재현 방법](./docs/benchmarks/README.md)을 공개합니다.

### 추가 기능과 기술 보완

- 모집자가 **즉시 참가 / 승인제**를 선택합니다. 승인제에서는 참가 소개를 보내고 모집자가 승인·거절합니다. 마지막 자리의 동시 승인도 정원을 초과하지 않습니다.
- 신청·승인·댓글·일정 변경은 상단 알림함에서 확인하고 읽음 처리합니다. 여행의 진행·종료·취소 상태와 공유 일정 변경 이력을 제공합니다.
- 여러 탭에서 같은 계획을 수정하면 버전 충돌을 알려 이전 저장 내용을 보호합니다. 종료된 여행의 참가 기록은 유지합니다.
- 게시글·동행·댓글을 신고하고 회원을 차단할 수 있습니다. 마이페이지에서 차단을 해제하고 신고 결과를 확인하며, 운영자는 별도 관리 화면에서 처리 사유를 기록합니다.
- DB 연결 풀, 목록 일괄 조회와 서버 페이지 검색을 적용했습니다. 비밀번호 복구·로그인 요청을 제한하고 비밀번호 변경 시 기존 세션을 무효화합니다.
- GitHub/GitLab CI, 상태 확인 API, 백업·분리 DB 복구, Caddy HTTPS 배포 구성을 추가했습니다. **현재는 로컬 실행이며 공개 서버에 배포하지 않았습니다.**

## 데이터베이스 설계 — ERD

![업무 테이블 19개와 마이그레이션 이력 테이블의 관계와 주요 키](./docs/diagrams/erd.png)

[ERD 크게 보기](./docs/diagrams/erd.png) · [편집 가능한 ERD 원본](./docs/diagrams/erd.excalidraw) · [전체 컬럼·자료형·제약조건 DDL](./db/schema-current.sql)

그림은 주요 컬럼과 FK 관계를 도메인별로 나누어 보여줍니다. 점선의 참조 카드는 같은 테이블을 다른 패널에서 다시 표시한 것이며 테이블이 추가되는 것은 아닙니다. `hotplaces`는 기존 설계·검증 이력과 호환되는 예약 테이블로 현재 사진 등록 API·화면은 연결하지 않습니다. 관계의 NULL 허용 여부와 전체 컬럼·인덱스는 DDL이 최종 기준입니다.

| 구분 | 테이블 |
| --- | --- |
| 관광정보·기준 데이터 | `sidos`, `guguns`, `contenttypes`, `attractions` |
| 회원·계획·찜 | `members`, `plans`, `plan_items`, `favorites` |
| 동행 | `companions`, `companion_participants` |
| 커뮤니티 | `posts`, `comments` |
| 승인·알림·변경 이력 | `companion_requests`, `notifications`, `plan_revisions` |
| 복구·신고·차단 | `password_reset_tokens`, `reports`, `member_blocks` |
| 스키마 이력 | `schema_migrations` |
| 예약 | `hotplaces` |

시도·구군은 복합 FK로 올바른 지역 조합을 검증하고, 계획당 모집글은 UNIQUE로 제한합니다. 참가·찜은 복합 PK로 중복을 막고, 댓글은 게시글 또는 동행 중 한 대상만 참조하도록 CHECK를 둡니다. 여행 기간은 1~14일, 동행 정원은 모집자 포함 2~10명입니다. [AI 검토·개선 기록](./db/AI_REVIEW.md)과 [SQL 검증 결과](./docs/validation/2026-11-08-sql.txt)를 함께 제공합니다.

## 실행 방법

Docker Desktop 실행 후 저장소 루트에서:

```sh
docker compose up -d --build
```

http://localhost:8080/mapmates/index.html 에 접속합니다. 첫 빌드는 이미지·Maven 의존성을 다운로드하며 DB 초기화에는 관광지 50,915행을 적재합니다. 기존 MySQL이 필요하지 않고 호스트에 DB 포트를 공개하지 않습니다. 데이터는 Docker 볼륨에 보존됩니다. 로컬 복구 이메일은 http://localhost:8026 에서 확인합니다. 종료는 `docker compose down`으로 합니다.

시연 계정은 `traveler1@mapmates.test` ~ `traveler10@mapmates.test`, 비밀번호는 `travel1234`입니다. 10번은 운영자입니다. 초기 데이터는 회원 10명, 계획·동행 각 1개, 게시글 2개, 댓글 1개입니다. 프론트 단독 실행의 체험 데이터와 별개입니다.

### 카카오맵과 외부 API

루트 `.env`에 로컬 키를 넣습니다. `.env`는 커밋하지 않습니다.

```dotenv
MAPMATES_KAKAO_JS_KEY=발급받은_JavaScript_키
MAPMATES_KAKAO_REST_KEY=발급받은_모빌리티_REST_키
MAPMATES_WEATHER_API_KEY=기상청_키
MAPMATES_EV_CHARGER_API_KEY=충전소_키
```

설정 변경 후 `docker compose up -d web`으로 반영합니다. 카카오 JavaScript SDK 도메인에는 **`http://localhost:8080`**, **`http://127.0.0.1:8080`**을 등록합니다. `https://`와 `http://`는 다르며 `/mapmates` 경로는 도메인 등록에 넣지 않습니다. 카카오맵 서비스 활성화도 필요합니다.

`/mapmates/config.js`는 브라우저용 설정만 제공합니다. 모빌리티 REST 키는 서버에서만 사용합니다. 관광지 검색은 동봉한 관광정보 DB를 사용하므로 TourAPI 키 없이 동작합니다. 지도·날씨·충전 현황 등 외부 서비스는 해당 키와 API 사용 권한이 필요합니다.

### Docker 없이 실행하기

Docker 없이 실행하려면 새 MySQL 8 DB에 `db/schema-current.sql`, `USE ssafy_trip;`를 `USE mapmates;`로 바꾼 관광지 덤프, `db/init/03-clean.sql`, `db/seed.sql` 순으로 적재합니다. **스키마 전체 파일은 새 DB 구축용이며 기존 서비스 DB에 재실행하지 않습니다.** 기존 Docker DB는 `python3 scripts/migrate.py`로 미적용 변경만 반영한 뒤 웹 이미지를 다시 빌드합니다. 전체 DDL은 기준 스키마와 변경 SQL에서 생성한 파일입니다.

환경변수 `MAPMATES_DB_URL`, `MAPMATES_DB_USER`, `MAPMATES_DB_PASSWORD`를 설정하거나 `back/src/main/resources/application.properties.example`을 복사해 설정합니다. Java 17 이상과 Maven으로 `mvn -f back/pom.xml verify` 후 `back/target/mapmates.war`를 Tomcat 10.1에 배포합니다.

프론트만 확인하려면 `node front/dev-server.js`를 사용합니다. 이 경우 브라우저 데모 모드이며 서버에 데이터를 저장하지 않습니다. 서버 모드는 DB 장애를 데모 데이터로 숨기지 않습니다.

### 프론트 단독 데모 실행과 기존 설정

기존 프론트 개발 서버·설정 예시도 유지합니다. 이 모드는 브라우저 체험 데이터로 동작합니다.

```sh
cp front/config.example.js front/config.js
node front/dev-server.js
```

[http://localhost:5500](http://localhost:5500)에서 확인합니다. 프론트 전용 `config.js`의 지도·TourAPI·날씨·충전소 설정과 사용법은 [기존 프론트 안내](./front/README.md#실행-방법)에 보존했습니다. 서버 모드에서는 루트 `.env`와 `/mapmates/config.js`를 사용합니다.

## 데이터 저장 방식

| 데이터 | 서버 실행 | 프론트 단독 데모 |
| --- | --- | --- |
| 회원·프로필·비밀번호 | MySQL, 비밀번호는 PBKDF2 해시 | 기존 브라우저 체험 데이터 |
| 로그인 | 서버 HttpSession·쿠키 | 브라우저 데모 상태 |
| 저장 계획·일정·찜 | MySQL | localStorage |
| 동행·참가·게시글·댓글 | MySQL, 다른 브라우저와 공유 | 같은 브라우저의 체험 상태 |
| 작성 중 초안·지도 설정 | 사용자별 localStorage | localStorage |
| 인기 장소 | 전체 회원 DB 계획 집계 | 현재 브라우저의 계획 집계 |

서버 모드는 기존 데모 계정·평문 비밀번호를 자동으로 서버에 옮기지 않습니다. 브라우저 저장소를 지워도 DB에 저장한 데이터는 유지됩니다. 초기 시연 데이터의 규모와 계정은 위 실행 방법을 참고하세요.

API 테스트는 별도 검증 계정을 만들고 종료 시 삭제합니다. 브라우저 테스트는 시연 계정으로 생성한 계획·게시글을 정리합니다. 기존 DB 검증은 별도 `mapmates_erd_check` 스키마에서 실행합니다.

Java 단위 테스트 4개, SQL 33개, HTTP 통합 7개 시나리오, 브라우저 12개 항목이 통과했습니다. 추가 기능 API 9개 시나리오와 기능 브라우저 8개 항목도 통과했으며 실제 카카오 SDK·지도 타일·DB 관광지 표시도 확인했습니다. [통합 검증 보고서](./docs/VALIDATION.md)에 결과와 화면을 정리했습니다. 외부 날씨·충전소·차량 경로는 각 서비스의 키와 사용 권한이 필요합니다.

프론트 단계의 기존 검증과 문제 해결 과정도 보존합니다. [기능 검증 보고서](./front/docs/FEATURE_AUDIT.md), [트러블슈팅](./front/docs/TROUBLE_SHOOTING.md), [알고리즘 검증](./front/docs/ALGORITHM_IMPROVEMENTS.md)을 참고하세요.
